Privacy policy.

The Rails Profiler Chrome extension talks only to the profiler servers you configure. No telemetry, no analytics, no third party.

Publisher: Sébastien Duplessy. Last updated: 2026-10-27.

Data storage

The extension stores the following data locally, in your browser:

  • Settings. The list of profiler origins you configured (the first one is the reference), the editor link settings, the slave detection rule, the slow request threshold and whether the in-page bar is on, kept in chrome.storage.sync. Chrome may sync them across your own devices if you turned browser sync on.
  • Profiled requests. A list of up to 100 profiled HTTP requests per browser tab, kept in chrome.storage.session. Each entry holds the URL of the request, the HTTP method, the request timestamp and the profile token. Once retrieved from the profiler server, an entry may also hold the HTTP status code and the request duration, or a flag saying the summary could not be retrieved. Full profile details are not stored. A tab never sees the list of another tab. The list of a tab is erased when the tab is closed, when you clear it in the panel, and when the browser restarts or the extension is reloaded.
  • Panel state. The slave you picked for a tab, the connectivity test result of each origin and, per tab, the slow query count and token of the latest request (for the toolbar badge), kept in chrome.storage.session. The per-tab entries are erased when the tab is closed, all of it when the browser restarts.
  • In-page bar state. Whether you hid the bar in a tab, kept inchrome.storage.session where the page cannot read it, and erased when the tab is closed. The request details and outgoing HTTP calls the bar shows are fetched from your profiler server when you open them and kept in the page's memory only.
  • Theme. Your light or dark choice for the panel, kept in the extension's own localStorage, which survives browser restarts.

None of this data leaves your computer, except as described below.

Data transmission

The extension only communicates with the Rails profiler servers you configure, and with the cluster slaves your master server lists. It makes:

  • HTTP requests to the profiler API endpoints (/_profiler/api/*) of those servers to fetch request profiles, profile summaries, the cluster slave list and other profiling data;
  • HTTP requests to the configured origins to test connectivity;
  • when you confirm it in the panel, a replay of a request you chose, sent to the selected cluster slave, otherwise to the origin that recorded the request, using the replay endpoint of the profiler gem;
  • when you confirm it in the panel, a request asking the profiler to delete all the profiles it stores (DELETE /_profiler/api/profiles/clear).

Copying a request URL or a cURL command writes it to your clipboard when you click, and sends it nowhere. Cookies and authorization headers are left out of the cURL command unless you tick the box to include them. Clicking a source link opens your editor through the URL scheme you chose.

No data is sent to any third-party service, analytics platform or external server. The extension does not collect telemetry, usage statistics or any browsing data outside the origins you configured.

Data use

The stored data is used exclusively to:

  • display request profiling information and the slow query badge in the DevTools panel;
  • display the in-page bar on pages of the origins you granted that have no toolbar from the gem;
  • test connectivity to your configured profiler servers;
  • carry out the actions you trigger: replay, copy, delete the stored profiles, open a profile in a new tab.

Your data is not sold, shared or used for any other purpose.

Chrome permissions

Each permission the extension requests, and why:

  • storage. Keeps the settings and the request metadata described above.
  • scripting. Registers content scripts, only on the origins you configured and granted: two capture request tokens, and a third draws the in-page profiler bar on pages without the gem's toolbar, unless you turn the bar off in the settings. The bar is the only thing added to those pages. No script runs on any other origin.
  • webRequest. Observes the responses of page loads and of XHR or fetch calls, to find the x-profiler-token header. It reads only that header, only for origins you granted. Observation only: requests are never blocked or modified.
  • Host access (optional). Requested at runtime, one origin at a time, when you add a profiler origin or pick a cluster slave. Chrome asks you each time, and nothing is read from an origin before you accept. A wildcard such ashttps://*.myapp.test is accepted only in Chrome's native form, and overly broad patterns are refused.

The extension executes no remote code: every script is bundled with it at build time.

This website

This site is static. It sets no cookies, loads no third-party script or font, and runs no analytics or tracker.
