Rails Profiler in Chrome DevTools.

The extension adds a Rails Profiler panel to DevTools. It lists the profiled requests of the page you are browsing, page loads and fetch or XHR calls alike, and shows the full profile of each one next to the page. On a front end or a single page app, where Rails renders no toolbar, it can also draw its own profiler bar at the bottom of the page.

Add to ChromeFrom the Chrome Web Store. Works in Chrome, Edge and Brave.

A viewer, not a second dashboard

The panel does not reimplement the profiler. When you select a request, it loads the dashboard served by your own Rails app, <base URL>/_profiler/profiles/<token>?embed=true, in an iframe. What you see in DevTools is the dashboard of the gem you installed, tab for tab, so it always matches that gem's version.

On the profiler origin, the extension wraps fetch and XMLHttpRequest and notes every response that carries an X-Profiler-Token header. It also reads the token the gem renders into the toolbar of HTML pages, and the response headers of pages that have no toolbar. The service worker keeps the 100 most recent requests for the browser session. The panel shows their method, URL, status, duration and time, newest first, with a filter, and opens the first request by itself when nothing is selected.

A profile stays live while it is open: if the gem saves it again, for example when a background job finishes after the page, the panel reloads it. It checks often at first, then every 30 seconds, and stops after 10 minutes without a new save.

A profiler bar for front ends and single page apps

The gem puts its toolbar into the HTML pages Rails renders. A separate front end or a single page app calling a Rails API gets no such page: only the API responses carry X-Profiler-Token. For that case the extension draws its own bar across the bottom of the page, without opening DevTools. It uses the gem's toolbar palette, value for value, in dark and light, and follows the theme you chose in the gem on that origin, else the system's.

  • Collapsed, it is one 32 px line: an alert dot (red when a request of the page answered 4xx or 5xx, orange when one was slow or ran slow queries, green otherwise), the counters (7 calls, 2 errors), the last API call with its method, path, status and duration, and the SQL and outgoing HTTP totals of the page.
  • Expanded, it lists the latest 20 API calls of the page as they happen, with All, Errors and Slow filters and a search on the path. A row opens its detail in place: status, duration, SQL count and time, slow queries, outgoing HTTP calls, and a link to the full profile in the gem's dashboard.
  • Outbound HTTP, its second tab, lists the calls your Rails app made to third parties while it served those requests, with the request each one came from. A call opens its full URL, status, duration, error, headers and bodies, as recorded by the gem, which has already redacted them.
  • Alt+P (Option+P on macOS, the gem's own shortcut) hides and shows it, except while you type in a field. A setting turns it off altogether; it is on by default.
  • It never doubles the gem's toolbar: on a page where the gem rendered its own, the extension shows nothing.

The bar is the only thing the extension adds to a page, and only on the origins you listed in its settings and granted access to. So for a front end served from its own origin, for example its own dev server, add that origin in the settings. The bar overlays the last 32 px of the page and reserves no space; it reads its numbers from the gem's toolbar route and stores none of the details.

Access to the origins you choose, nothing else

Installed, the extension has access to no website at all. It works on the origins you grant, one at a time: the scheme, host and port of each profiler URL you set in its settings, by default http://localhost:3000.

  1. You open the settings page (it opens by itself after install, or from the gear in the panel) and set the protocol, host and port of your Rails app.
  2. Save stores the URL, then asks the browser for access to that origin alone, for example http://localhost:3000/*. You accept or refuse the prompt.
  3. Once access is granted, the extension registers its scripts for that origin. There it adds nothing to the page but its own bar, on pages without the gem's toolbar. On every other site it injects nothing and reads nothing.
  4. Whenever it starts, the URL changes or a permission is added, the service worker removes any other site access the extension holds. Removing access never needs a prompt.

This is a deliberate change: versions 1.0.2 and earlier requested access to every site. After an update from one of them, that broad access is removed automatically and the settings page opens, so you save the profiler URL once and accept the prompt. If you refuse it, the URL is saved but profiling stays off until you save again. You can withdraw the access at any time under "Site access" on the extension's details page.

One consequence to know: only pages of that exact origin are profiled. A front end on its own dev server, another port, or 127.0.0.1 instead of localhost is a different origin, so set the profiler URL to the origin of the pages you browse.

What the manifest asks for

storage
Saves the profiler URL (chrome.storage.sync) and keeps the request list when the browser stops the service worker (chrome.storage.session).
scripting
Registers the content scripts, the in-page bar included unless you turn it off, for the profiler origin only. They are not declared in the manifest, so nothing is injected anywhere else.
webRequest
Observes, never blocks or changes, the main frame response of a page of the profiler origin, and reads only its X-Profiler-Token header. It catches the pages the gem profiles without a toolbar: streamed HTML, send_file downloads, JSON or PDF opened in a tab.
optional_host_permissions
Declares http://*/* and https://*/* as optional only. Nothing is granted at install; the settings page requests the origin of the profiler URL and nothing else.

Requirements

  • A Rails app running the rails-profiler gem in development, reachable from the browser.
  • A Chromium based browser with Manifest V3 and DevTools extension support: Chrome, Edge or Brave. Chrome 102 or later is required.

Install

  1. Open the extension's page on the Chrome Web Store and clickAdd to Chrome.
  2. The settings page opens: check the profiler URL, click Save and accept the browser prompt that asks access to that site.
  3. Reload the tab you want to profile, open DevTools (F12) and pick the Rails Profiler tab.

If no requests appear

  • Check that the settings page says access is granted.
  • Check that the profiler URL has the same origin (scheme, host and port) as the page you browse, and that its responses carry an X-Profiler-Token header.
  • Reload the page after installing or reloading the extension.
  • If the panel stays empty or the iframe fails to load, open <base URL>/_profiler in a tab to check that the gem is mounted.
